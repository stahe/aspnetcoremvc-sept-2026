    3. Le modèle d'une action

    Une action a besoin des informations envoyées par le navigateur : les paramètres de l'URL ([?nom=martin&age=42]), les champs d'un formulaire, les paramètres de route. Le cours d'origine appelle modèle de l'action l'ensemble de ces informations. Ce chapitre montre comment [ASP.NET Core] les fournit à l'action, les convertit dans le bon type et les valide. Ce travail s'appelle la liaison de modèle ([model binding]).

    using Microsoft.AspNetCore.Mvc;

namespace Exemple07.Controllers;

[Route("parametres")]
public class ParametresController : Controller
{
    // /parametres/action01?nom=martin : le paramètre [nom] de l'URL -> le paramètre [nom] de l'action
    [HttpGet("action01")]
    public string Action01(string? nom)
    {
        return $"nom = [{nom}], de type {nom?.GetType().Name ?? "null"}";
    }

    // /parametres/action02?age=42 : la valeur est CONVERTIE dans le type du paramètre
    [HttpGet("action02")]
    public string Action02(int age)
    {
        return $"age = [{age}], de type {age.GetType().Name}, ModelState.IsValid = {ModelState.IsValid}";
    }

    // /parametres/action03?age=42 : int? distingue un paramètre absent (null) d'un zéro
    [HttpGet("action03")]
    public string Action03(int? age)
    {
        return $"age = [{age?.ToString() ?? "null"}], ModelState.IsValid = {ModelState.IsValid}";
    }

    // /parametres/action04?page=2 : une valeur par défaut si le paramètre manque
    [HttpGet("action04")]
    public string Action04(int page = 1)
    {
        return $"page = [{page}]";
    }

    // /parametres/action05?q=nest : [FromQuery(Name = ...)] quand les noms diffèrent
    [HttpGet("action05")]
    public string Action05([FromQuery(Name = "q")] string? recherche)
    {
        return $"recherche = [{recherche}]";
    }

    // /parametres/action06?nom=martin&age=42 : tous les paramètres d'un coup
    [HttpGet("action06")]
    public Dictionary<string, string> Action06()
    {
        return Request.Query.ToDictionary(p => p.Key, p => p.Value.ToString());
    }
}

    Commentons ce code :

    • lignes 10-12 : la liaison de modèle associe les paramètres de l'action aux données de la requête par leur nom : le paramètre [nom] de l'action reçoit la valeur du paramètre [nom] de l'URL (la partie qui suit le [?], appelée chaîne de requête ou [query string]). Le type [string?] indique que la valeur peut manquer : elle vaut alors [null]. [nom?.GetType().Name ?? "null"] : le nom du type de la valeur, ou la chaîne ["null"] si la valeur est [null] (l'opérateur [??] fournit une valeur de remplacement) ;
    • lignes 17-19 : le paramètre est déclaré de type [int] : la liaison de modèle convertit la chaîne reçue (["42"]) en nombre. Si la conversion échoue ([?age=abc]), l'action est quand même exécutée, avec la valeur par défaut du type (0 pour un [int]), et l'échec est noté dans [ModelState], l'état de la liaison de modèle : [ModelState.IsValid] vaut alors [false] ;
    • lignes 24-26 : avec le type [int?] (un entier « nullable »), un paramètre absent vaut [null], et non 0 : on peut distinguer « pas d'âge » de « âge 0 » ;
    • lignes 31-33 : une valeur par défaut [C#] remplace un paramètre absent ;
    • lignes 38-40 : l'attribut [[FromQuery(Name = "q")]] précise où chercher la valeur (dans l'URL) et sous quel nom : le paramètre [recherche] de l'action reçoit le paramètre [q] de l'URL ;
    • lignes 45-47 : [Request.Query] donne accès à tous les paramètres de l'URL, sans liaison ni conversion. [ToDictionary] ([LINQ]) en fait un dictionnaire, sérialisé en JSON.

    Les guillemets autour de l'URL sont nécessaires quand elle contient le caractère [&], qui a un sens particulier pour la console. On retiendra :

    • un paramètre est lié par son nom, sans tenir compte des majuscules ([?NOM=martin] convient aussi) ;
    • sa valeur est convertie dans le type déclaré. C'est une différence importante avec [NestJS], où le type d'un paramètre n'était qu'une déclaration [TypeScript], effacée à la compilation ;
    • une conversion impossible ne provoque pas d'erreur : l'action est exécutée avec une valeur par défaut, et c'est à elle de consulter [ModelState.IsValid]. Un type « nullable » ([int?]) évite de confondre une valeur absente ou invalide avec 0.

    Les caractères accentués et les espaces sont codés dans une URL ([%C3%A9] pour [é]...) : [ASP.NET Core] les décode avant la liaison.

    3.2. Exemple 08 : un modèle d'action décrit par une classe

    Quand une action a plusieurs paramètres, on les décrit par une classe. Chaque propriété de la classe porte des attributs de validation, fournis par l'espace de noms standard [System.ComponentModel.DataAnnotations]. C'est l'équivalent des décorateurs de la bibliothèque [class-validator] de [NestJS].

    using System.ComponentModel.DataAnnotations;

namespace Exemple08.Models;

// le modèle de l'action : une classe dont chaque propriété porte ses contraintes
public class PersonneModele
{
    [Required(ErrorMessage = "le nom est obligatoire")]
    [StringLength(20, MinimumLength = 2, ErrorMessage = "le nom doit avoir de 2 à 20 caractères")]
    public string? Nom { get; set; }

    [Required(ErrorMessage = "l'âge est obligatoire")]
    [Range(0, 150, ErrorMessage = "l'âge doit être compris entre 0 et 150")]
    public int? Age { get; set; }

    [Required(ErrorMessage = "le titre est obligatoire")]
    [AllowedValues("Mr", "Mme", "Melle", ErrorMessage = "titre inconnu")]
    public string? Titre { get; set; }

    // facultatif : pas de [Required]
    [EmailAddress(ErrorMessage = "adresse électronique invalide")]
    public string? Email { get; set; }
}

    Commentons ce code :

    • ligne 1 : l'espace de noms des attributs de validation ;
    • ligne 10 : chaque paramètre attendu est une propriété publique ([{ get; set; }] : on peut la lire et l'écrire). La liaison de modèle crée un objet [PersonneModele], puis remplit chaque propriété avec le paramètre de même nom ;
    • lignes 8-9 : le nom est obligatoire ([[Required]]) et doit avoir de 2 à 20 caractères ([[StringLength]]). Chaque attribut accepte un message d'erreur personnalisé ([ErrorMessage]). Les propriétés sont déclarées « nullables » ([string?], [int?]) : un paramètre peut toujours manquer dans une requête, et c'est [[Required]] qui l'exige ;
    • lignes 12-14 : l'âge est converti en entier, obligatoire, compris entre 0 et 150 ([[Range]]) ;
    • ligne 17 : le titre doit appartenir à une liste de valeurs ([[AllowedValues]], apparu avec [.NET] 8) ;
    • ligne 21 : l'adresse électronique est facultative (pas de [[Required]]) ; si elle est présente, elle doit être valide.

    using System.Net;
using Exemple09.Models;
using Microsoft.AspNetCore.Mvc;

namespace Exemple09.Controllers;

// pas de [ApiController] : l'action est TOUJOURS exécutée, et c'est elle qui
// décide de ce qu'elle fait d'un modèle invalide
[Route("personnes")]
public class PersonnesController : Controller
{
    [HttpGet("action01")]
    public ContentResult Action01(PersonneModele personne)
    {
        // ModelState : le résultat de la liaison ET de la validation du modèle
        if (ModelState.IsValid)
        {
            return Page($"<p>Bienvenue {personne.Titre} {personne.Nom} ({personne.Age} ans)</p>");
        }
        // les erreurs, champ par champ
        var items = ModelState
            .Where(champ => champ.Value!.Errors.Count > 0)
            .Select(champ => $"<li>{champ.Key} : {string.Join(", ", champ.Value!.Errors.Select(e => e.ErrorMessage))}</li>");
        return Page($"<p>Le formulaire contient des erreurs :</p><ul>{string.Join("", items)}</ul>");
    }

    // une page HTML (code 200 dans les deux cas)
    private ContentResult Page(string html) => Content(html, "text/html; charset=utf-8");
}

    Commentons ce code :

    • ligne 9 : sans [[ApiController]], l'action est toujours exécutée, que le modèle soit valide ou non. Un paramètre de type classe est cherché partout : dans l'URL, dans les champs d'un formulaire, dans la route ;
    • ligne 13 : la liaison de modèle et la validation ont été faites avant l'exécution de l'action : l'objet [personne] est rempli, et [ModelState] contient les erreurs éventuelles ;
    • lignes 16-18 : pas d'erreur : une page de bienvenue ;
    • lignes 21-23 : sinon, la liste des erreurs. [ModelState] est un dictionnaire dont chaque clé est le nom d'un champ ([Nom], [Age]...) et chaque valeur l'état de ce champ, avec sa liste d'erreurs ([Errors]). Les méthodes [LINQ] [Where] (filtrer) et [Select] (transformer) gardent les champs en erreur, et fabriquent une ligne HTML par champ. [!] affirme au compilateur qu'une valeur n'est pas [null] ;
    • ligne 24 : une page qui liste les erreurs ;
    • ligne 28 : dans les deux cas la réponse est une page HTML, avec le code 200.

    using System.ComponentModel.DataAnnotations;

namespace Exemple10.Models;

// IValidatableObject : une validation écrite en C#, pour ce que les attributs
// ne savent pas exprimer (ici : CHAQUE élément de la liste)
public class ChoixModele : IValidatableObject
{
    private static readonly string[] Couleurs = ["rouge", "vert", "bleu"];

    [MinLength(1, ErrorMessage = "choisissez au moins une couleur")]
    public List<string> Couleur { get; set; } = [];

    public IEnumerable<ValidationResult> Validate(ValidationContext contexte)
    {
        foreach (var couleur in Couleur.Where(c => !Couleurs.Contains(c)))
        {
            // yield return : la méthode rend les erreurs une par une
            yield return new ValidationResult($"couleur inconnue : {couleur}", [nameof(Couleur)]);
        }
    }
}

    Commentons ce code :

    • ligne 7 : la classe implémente l'interface [IValidatableObject] : une validation écrite en [C#], pour ce que les attributs ne savent pas exprimer ;

    [HttpPost("action04")]
    public object Action04([FromForm] PersonneModele personne)
    {
        return new
        {
            personne,
            valide = ModelState.IsValid,
            erreurs = ModelState.Values.SelectMany(v => v.Errors).Select(e => e.ErrorMessage),
        };
    }
}

    Un model binder est l'objet qui fabrique la valeur d'un paramètre à partir de la requête. [ASP.NET Core] en fournit pour tous les types courants ; on peut écrire les siens. Le fichier [Liaison/DateFrBinder.cs] :

    using System.Globalization;
using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Exemple12.Liaison;

// un "model binder" : transforme une date française "23/09/2026" en DateOnly
public class DateFrBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext contexte)
    {
        // la valeur brute, trouvée dans l'URL, le formulaire, la route...
        var brut = contexte.ValueProvider.GetValue(contexte.ModelName).FirstValue;
        if (DateOnly.TryParseExact(brut, "dd/MM/yyyy", CultureInfo.InvariantCulture, DateTimeStyles.None, out var date))
        {
            // succès : la valeur que recevra l'action
            contexte.Result = ModelBindingResult.Success(date);
        }
        else
        {
            // échec : une erreur dans ModelState ("31/02/2026" est refusée aussi)
            contexte.ModelState.AddModelError(contexte.ModelName, $"[{brut}] n'est pas une date jj/mm/aaaa valide");
        }
        return Task.CompletedTask;
    }
}
    • ligne 7 : un model binder implémente l'interface [IModelBinder] ;
    • ligne 9 : sa méthode [BindModelAsync] reçoit le contexte de la liaison : le nom du paramètre ([ModelName]), les sources de valeurs ([ValueProvider] : l'URL, le formulaire, la route...), [ModelState]... ;
    • ligne 12 : la valeur brute du paramètre ([FirstValue] : la première, s'il y en a plusieurs) ;
    • lignes 13-16 : [DateOnly.TryParseExact] convertit une chaîne au format [jj/mm/aaaa] en [DateOnly] (une date sans heure), et rend [false] si c'est impossible, y compris pour une date qui n'existe pas (31/02/2026). En cas de succès, [ModelBindingResult.Success(date)] fournit la valeur que recevra l'action ;
    • ligne 21 : en cas d'échec, une erreur est ajoutée à [ModelState] ;
    • ligne 23 : la méthode est asynchrone par nature ([Task]), mais n'a rien à attendre : elle rend une tâche déjà terminée.

    using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Exemple12.Liaison;

// la langue préférée du navigateur, lue dans l'entête
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LangueBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext contexte)
    {
        var entete = contexte.HttpContext.Request.Headers.AcceptLanguage.ToString();
        var premiere = entete.Split(',')[0].Trim();
        var langue = premiere.Length >= 2 ? premiere[..2].ToLowerInvariant() : "fr";
        contexte.Result = ModelBindingResult.Success(langue);
        return Task.CompletedTask;
    }
}
    • ligne 11 : l'entête [Accept-Language], qui indique les langues préférées de l'utilisateur ;
    • lignes 12-13 : les deux premières lettres de la première langue. [premiere[..2]] est une plage ([range]) : les caractères d'indice 0 et 1.

    using System.ComponentModel.DataAnnotations;

namespace Exemple12.Liaison;

// un attribut de validation "maison" : [SansEspace]
public class SansEspaceAttribute : ValidationAttribute
{
    public SansEspaceAttribute() : base("le champ {0} ne doit pas contenir d'espace")
    {
    }

    public override bool IsValid(object? valeur)
    {
        // null est accepté : c'est le rôle de [Required] de l'exiger
        return valeur is not string texte || !texte.Contains(' ');
    }
}
    • ligne 6 : un attribut de validation hérite de [ValidationAttribute]. Par convention, le nom d'une classe d'attribut se termine par [Attribute], que l'on omet à l'usage : [[SansEspace]] ;
    • ligne 8 : le message d'erreur par défaut, transmis à la classe mère. [{0}] sera remplacé par le nom du champ ;
    • lignes 12-15 : la règle. [valeur is not string texte] : si la valeur n'est pas une chaîne ([null], par exemple), elle est acceptée ; sinon, elle est affectée à la variable [texte], qui ne doit pas contenir d'espace. L'étude de cas a un attribut de ce genre, [[Parmi]].

    {
        if (!ModelState.IsValid)
        {

        return Ok($"agenda du jour [{jour:yyyy-MM-dd}]");

    3.6.5. Conclusion

    Le modèle d'une action est construit par la liaison de modèle à partir de la requête : paramètres de route, de l'URL, champs du formulaire, corps JSON, entêtes. Les valeurs sont converties dans le type des paramètres, puis validées par les attributs. Le résultat de ces deux étapes est dans [ModelState]. Pour un serveur JSON, [[ApiController]] refuse automatiquement un modèle invalide ; pour une application HTML, l'action teste elle-même [ModelState.IsValid] (exemple 09), afin de pouvoir réafficher le formulaire. C'est l'objet du chapitre suivant.
